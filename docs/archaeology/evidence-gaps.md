# LORE archaeology evidence gaps

The baseline is intentionally incomplete. These gaps must remain visible rather than being inferred from the current architecture.

## Missing causal arcs

- bootstrap trust-root evolution and self-hosting corrections;
- extractor configuration and repository-fact evolution;
- record identity, revision, supersession, and effective-status defects;
- proposal validation and source-state conflict handling;
- transactional rollback and generated-file replacement incidents;
- bounded context and hydration design;
- semantic diff and explanation behavior;
- offline lockfile restoration and clean-room verification;
- public package and CLI-only API boundary;
- release automation, versioned CLI compatibility, and pre-1.0 change policy;
- adoption by other repositories and the distinction between intended and tested interoperability;
- LORE's relationship to Deciduous, GitHub, Factory Floor, the control planes, and reusable maintenance skills.

## Evidence still required

Each future arc should identify exact commits, pull-request heads, merge commits, current paths, tests, incident or correction evidence, and the default-branch state against which the claim was reconciled.

Open branches and proposals must remain branch-only or proposed. Passing validation must not be generalized to package release, external adoption, production use, or historical correctness.

## Completion gate

The graph may be relabeled complete only after:

1. all material arcs are reconstructed from repository evidence;
2. failed and superseded approaches are preserved;
3. the current default branch is reconciled;
4. exact tested heads and merge ancestry are recorded separately;
5. cross-repository claims have reciprocal evidence;
6. privacy review passes on every public projection;
7. an independent reviewer accepts the historical reconstruction.
